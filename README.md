# Workout Planner

Веб-приложение для планирования тренировок. Позволяет составлять упражнения, дневные и календарные шаблоны тренировок, ставить цели и отслеживать прогресс.

---

## Стек технологий

### Python 3.13


**Преимущества:** читаемый синтаксис, богатая экосистема библиотек, быстрый старт.  
**Недостатки:** GIL ограничивает параллелизм на уровне потоков; для CPU-интенсивных задач нужны workaround'ы (multiprocessing, asyncio).

---

### FastAPI

Веб-фреймворк для построения REST API. Обрабатывает HTTP-запросы, маршрутизацию, зависимости и автоматически генерирует документацию OpenAPI (Swagger).

**Преимущества:** автоматическая валидация через Pydantic, встроенная документация по `/docs`, нативная поддержка async, высокая производительность среди Python-фреймворков.  
**Недостатки:** для небольших проектов избыточен по сравнению с Flask; async-модель требует понимания event loop при смешивании синхронного и асинхронного кода.

---

### Pydantic v2

Библиотека валидации данных. Все входящие и исходящие данные API описываются схемами — Pydantic проверяет типы, форматы и ограничения автоматически.

**Преимущества:** декларативное описание структур, понятные сообщения об ошибках, тесная интеграция с FastAPI, v2 значительно быстрее v1.  
**Недостатки:** при сложных схемах с вложенными моделями конфигурация может стать громоздкой.

---

### SQLite + sqlite3 (стандартная библиотека)

База данных. SQLite хранит все данные в одном файле `.db` без отдельного сервера. Доступ через встроенный модуль `sqlite3` без ORM.

**Преимущества:** нулевая инфраструктура, простое резервное копирование (скопировать файл), достаточная производительность для однопользовательских и малонагруженных приложений.  
**Недостатки:** не подходит для высоких нагрузок и конкурентных записей; отсутствие ORM означает ручное написание SQL и сериализацию.

---

### JSON-поля в БД

Упражнения в дневных шаблонах и дни в календарных шаблонах хранятся как JSON-строки внутри текстовых полей. Это позволяет хранить переменное количество элементов без отдельных таблиц.

**Преимущества:** гибкость структуры, простота чтения и записи одним запросом.  
**Недостатки:** невозможно делать SQL-запросы по содержимому JSON; целостность данных внутри JSON не гарантируется на уровне БД; изменение одного элемента требует перезаписи всего поля.

---

### JWT (JSON Web Tokens)

Механизм авторизации. После входа сервер выдаёт подписанный токен, который хранится в `httponly` cookie. При каждом запросе токен проверяется и из него извлекаются данные пользователя.

**Преимущества:** stateless — сервер не хранит сессии; легко масштабируется; `httponly` cookie защищает от XSS.  
**Недостатки:** токен нельзя инвалидировать до истечения срока без blacklist; при компрометации секретного ключа все токены становятся уязвимы.

---

### bcrypt

Библиотека хеширования паролей. Пароли никогда не хранятся в открытом виде — только хеш с солью.

**Преимущества:** специально разработан для паролей; медленный по дизайну (параметр `rounds`), что затрудняет брутфорс; автоматически добавляет соль.  
**Недостатки:** медленнее других хеш-функций — это намеренно, но создаёт нагрузку при большом количестве одновременных авторизаций.

---

### Jinja2

Шаблонизатор для генерации HTML на сервере. Каждая страница рендерится на бэкенде и отдаётся браузеру готовым HTML.

**Преимущества:** простота, нет необходимости в отдельном фронтенд-фреймворке, автоматическое экранирование HTML защищает от XSS.  
**Недостатки:** каждый переход между страницами — отдельный HTTP-запрос и полная перезагрузка; динамические обновления требуют JavaScript поверх шаблонов.


---

### Docker + Docker Compose

Контейнеризация приложения. `Dockerfile` описывает образ, `docker-compose.yml` — конфигурацию запуска с томами для БД и логов.

**Преимущества:** воспроизводимое окружение на любой машине; простой деплой; изоляция от системных зависимостей.  
**Недостатки:** overhead при разработке; для SQLite контейнеризация даёт меньше преимуществ, чем для приложений с отдельным сервером БД.

## Архитектура

```
браузер
  │  HTTP (cookie-авторизация)
  ▼
FastAPI (main.py)
  ├── AuthMiddleware       — проверка токена, редирект на /login
  ├── pages.py             — HTML-страницы (Jinja2)
  ├── users.py             — /users/*
  ├── exercises.py         — /exercises/*
  ├── daily_templates.py   — /daily-templates/*
  ├── monthly_templates.py — /monthly-templates/*
  └── goals.py             — /goals/*
        │
        ▼
  functions.py             — бизнес-логика
        │
        ▼
  database.py              — sqlite3
        │
        ▼
  users_database.db        — файл БД
```

Фронтенд получает HTML от Jinja2, затем загружает данные через `fetch` к JSON API и обновляет страницу без перезагрузки.

## Структура проекта

```
├── main.py                  # точка входа, настройка приложения
├── database.py              # класс Database, работа с sqlite3

├── schemas.py               # Pydantic-схемы валидации
├── utils.py                 # JWT, bcrypt, get_current_user
├── dependencies.py          # get_db dependency для FastAPI
├── middleware.py            # AuthMiddleware
├── pages.py                 # HTML-роутер
├── users.py                 # API-роутер пользователей
├── exercises.py             # API-роутер упражнений
├── daily_templates.py       # API-роутер дневных шаблонов
├── monthly_templates.py     # API-роутер календарных шаблонов
├── goals.py                 # API-роутер целей
├── requirements.txt
├── Dockerfile
├── docker-compose.yml
├── secrets.env              # без коммита
├── static/
│   ├── css/main.css
│   └── js/main.js
├── templates/               # Jinja2 HTML-шаблоны
├── data/                    # файл БД (без коммита)
└── logs/                    # логи приложения (без коммита)
```

## Запуск

### Локально

```bash
# Установить зависимости
pip install -r requirements.txt

# Создать secrets.env
cp .env.example secrets.env
# Отредактировать secrets.env — прописать JWT_SECRET_KEY и DB_PATH

# Запустить
python main.py
```

### Docker

```bash
# Создать папки и скопировать БД
mkdir -p data logs
cp your_database.db data/

# Собрать и запустить
docker compose up --build

# В фоне
docker compose up -d --build
```

Приложение доступно на `http://localhost:8000`.
